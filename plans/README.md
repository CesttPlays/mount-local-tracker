## Findings considered and rejected

- **`/mtlz reset` could `wipe(nil)` if run before `ADDON_LOADED`** (`Core.lua:316`):
  not worth doing — the slash handler is registered at file load but `ADDON_LOADED`
  for this addon fires before `PLAYER_LOGIN`, before the player can type in chat;
  effectively unreachable. A one-line `if not addon.db then return end` guard is
  fine to add opportunistically but does not warrant its own plan.
- **Generator interpolates values into emitted Lua without escaping**
  (`tools/generate_mount_zones.py` `render_lua`): the only non-numeric interpolated
  value is `build_id` (a regex-matched version string like `12.1.0.69497`);
  `source`/`subcat` are fixed enum strings, ids are ints, and both the generator's
  `check_sanity` and `refresh-mount-data.yml`'s `lua5.1 -e "assert(loadfile(...))"`
  step catch malformed output. No action.
- **`Map.lua` does not check the return of `AddMinimapIconMap`** (only the world-map
  one is guarded): cosmetic; a mis-placed minimap pin is self-correcting on the
  next map move. Not worth a plan.
- **Security**: no runtime network, no secrets in the repo; workflow secrets
  (`CF_API_KEY`, `GITHUB_TOKEN`) are correctly scoped to the `deploy` environment.
  Nothing to do.
