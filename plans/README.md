## Localization batch (008–010)

Ported from `achivement-local-tracker/plans/005`–`007` (the design exploration).
The addon already gets every mount / zone / expansion **name** localized from the
WoW client; the only translatable surface is the ~90 hardcoded English "glue"
strings the addon writes itself (chat/slash output, the options panel, window
title + summary line, group-header labels, the obtainability tooltip block, the
right-click menu, the minimap tooltip).

- **008 must land first.** It adds the `addon.L` layer + AceLocale-3.0 + the
  `Locales/` tree + test scaffolding, changing **no** displayed string.
- **009 depends on 008** — the behaviour-visible change (every string resolves
  through `L`). Byte-identical on an enUS client; the risk is a dropped string or
  a broken `:format`, which the in-game checklist covers. Ends with an in-game
  `/reload` pass the maintainer must run before 010's docs step.
- **010 depends on 008** for the final `enUS.lua` phrase set. Its scripts +
  `refresh-locales.yml` can be built and dry-run now, but the **live** CF
  push/pull is BLOCKED: the mount addon has no CurseForge project yet (no
  `## X-Curse-Project-ID`, no `CF_API_KEY` / `deploy` environment — same gate as
  `context/immediate-next-steps.md`). The workflow ships dispatch-only
  (`schedule:` commented out). Its docs sub-step also needs 009 validated
  in-game (repo rule: README/CURSEFORGE updated only after in-game validation).
- 009 touches `tests/smoke.lua`; so does 008. On separate branches they conflict
  trivially there — merge by hand.

**Out of scope for the whole batch:** `MountData.lua` / `Overrides.lua` /
`tools/generate_mount_zones.py` (no translatable content); curated *data* strings
shown verbatim from `Overrides.lua` (`lockout` "daily"/"weekly", `dropChance`,
free-text `note`); slash keywords, STATE tokens
(`available/farmable/drop/…/collected`), `windowStyle` / `groupBy` values,
source-type keys, the `MTLZ_` setting prefix, `Alliance`/`Horde` API constants,
`## Title` / `SavedVariables` identity strings.

## Findings considered and rejected

- **`/mtlz reset` could `wipe(nil)` if run before `ADDON_LOADED`** (`Core.lua:316`):
  not worth doing — the slash handler is registered at file load but `ADDON_LOADED`
  for this addon fires before `PLAYER_LOGIN`, before the player can type in chat;
  effectively unreachable. A one-line `if not addon.db then return end` guard is
  fine to add opportunistically but does not warrant its own plan.
- **Generator interpolates values into emitted Lua without escaping**
  (`tools/generate_mount_zones.py` `render_lua`): the only non-numeric interpolated
  value is `build_id` (a regex-matched version string like `12.1.0.69497`);
  `source`/`subcat` are fixed enum strings, ids are ints, and both the generator's
  `check_sanity` and `refresh-mount-data.yml`'s `lua5.1 -e "assert(loadfile(...))"`
  step catch malformed output. No action.
- **`Map.lua` does not check the return of `AddMinimapIconMap`** (only the world-map
  one is guarded): cosmetic; a mis-placed minimap pin is self-correcting on the
  next map move. Not worth a plan.
- **Security**: no runtime network, no secrets in the repo; workflow secrets
  (`CF_API_KEY`, `GITHUB_TOKEN`) are correctly scoped to the `deploy` environment.
  Nothing to do.
